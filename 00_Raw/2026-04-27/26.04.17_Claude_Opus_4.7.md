## 3️⃣ 에이전트 강화 [[에이전트 강화]]

### 장기 태스크 신뢰성

- 툴 호출 오류 감소 / 루프 저항성(loop resistance) 향상
- 멀티스텝 워크플로우 일관성 개선
- **메모리 안정성**: 스크래치패드·노트 파일에 쓰고 읽는 장기 세션에서 컨텍스트 유실 감소
- 멀티 세션에 걸친 작업 추적 능력 강화

### Task Budget (베타) 🆕

- 에이전트 루프 전체(thinking + 툴 콜 + 출력)에 **토큰 예산** 할당
- 남은 토큰 카운트다운을 모델이 실시간으로 보고 작업 우선순위 조정
- 예산 소진 시 graceful finish (갑작스런 중단 아님)
- 베타 헤더: `task-budgets-2026-03-13`

```python
response = client.beta.messages.create(
    model="claude-opus-4-7",
    max_tokens=128000,
    output_config={
        "effort": "high",
        "task_budget": {"type": "tokens", "total": 128000},
    },
    betas=["task-budgets-2026-03-13"],
)
```

## 6️⃣ Claude Code 업데이트 [[Claude Code]]

### xhigh effort 레벨 🆕 [[xhigh effort]]

|레벨|설명|
|---|---|
|low|빠름, 경량 추론|
|medium|균형|
|high|기존 고성능 기본값|
|**xhigh**|🆕 high와 max 사이 — **Claude Code 신규 기본값**|
|max|최대 추론, 가장 느림|

- Anthropic 권장: 코딩·에이전트 작업은 `high` 또는 `xhigh`로 시작

- Claude Code 전용 세션 커맨드
- 코드 변경사항을 **꼼꼼히 리뷰**하는 전용 모드
- PR 제출 전 최종 검토, 보안 감사 등에 활용

## 8️⃣ 마이그레이션 주의사항 [[마이그레이션 주의]]

### ⚠️ 새 토크나이저

- 동일 입력 대비 토큰 수 **최대 1.35배(+35%)** 증가 가능
- `/v1/messages/count_tokens` 값이 달라짐
- `max_tokens` 파라미터에 여유 헤드룸 확보 필요

### ⚠️ Thinking 기본값 변경

- 기존: thinking 블록 내용 자동 노출
- 변경: **기본적으로 thinking 필드 비워짐** (silent change, 에러 없음)
- 추론 내용 필요 시 명시적으로 `"display": "summarized"` 설정 필요

```python
# thinking 복원 방법
output_config={
    "display": "summarized"
}
```

### ⚠️ 프롬프트 재튜닝 필요

- 인스트럭션 팔로잉이 더 엄격해졌으므로 기존 Opus 4.6 프롬프트 검토 필수
- 느슨한 지시에 의존하던 워크플로우는 명확한 지시로 업데이트 권장

### ✅ 비용 제어 팁

- `task_budget` + `effort` 조합으로 토큰 소비 관리
- 단, 과도한 제한은 모델 품질 저하 트레이드오프 발생

- ✅ 장기 에이전트 코딩 태스크 (수십~수백 스텝)
