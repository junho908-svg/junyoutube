## 5. Phase 4: jsDelivr CDN 동기화 확인

### 5.1 jsDelivr이란?

```
GitHub Repository
     ↓ (자동 동기화 1~2분)
jsDelivr CDN (전 세계 노드)
     ↓ (사용자에게 빠른 전송)
앱에서 이미지 표시
```

**특징**:
- 무료, 무제한
- 한국 서울 노드 포함 (빠름)
- HTTPS 자동 적용
- 자동 캐싱

### 5.2 URL 형식

```
https://cdn.jsdelivr.net/gh/{사용자명}/{저장소}@{브랜치}/{경로}/{파일명}

예시:
https://cdn.jsdelivr.net/gh/junho908-svg/family-worship-bgm@main/logomong/pose1_debut.png
```

### 5.3 작동 테스트

브라우저에서 위 URL 접속 → 데뷔 로고몽 이미지가 표시됨.

## 6. Phase 5: App.jsx 적용 + 배포

### 6.1 App.jsx 변경 내용

#### 추가된 코드 (LOGOMONG_VARIANTS 시스템)

```javascript
// v0.9.3: 로고몽 11가지 표정/포즈 (위치별 자동 매칭)
const toLogomongVariant = (filename) =>
  `https://cdn.jsdelivr.net/gh/${GITHUB_USER}/${GITHUB_REPO}@${GITHUB_BRANCH}/logomong/${filename}?v=1`;

const LOGOMONG_VARIANTS = {
  default:   LOGOMONG_URL,                              // 기존 (호환성)
  debut:     toLogomongVariant('pose1_debut.png'),      // 데뷔
  intro:     toLogomongVariant('pose2_intro.png'),      // 자기소개
  reveal:    toLogomongVariant('pose3_reveal.png'),     // 빛 호출
  hugging:   toLogomongVariant('pose4_hugging.png'),    // 책 안고
  welcome:   toLogomongVariant('pose5_welcome.png'),    // 환영
  winking:   toLogomongVariant('pose6_winking.png'),    // 윙크
  praying:   toLogomongVariant('bonus1_praying.png'),   // 기도
  surprised: toLogomongVariant('bonus2_surprised.png'), // 깜짝
  secret:    toLogomongVariant('bonus3_secret.png'),    // 쉿!
  sleeping:  toLogomongVariant('bonus4_sleeping.png'),  // 잠자는
  teaching:  toLogomongVariant('bonus5_teaching.png'),  // 가르치는
};
```

#### Logomong 컴포넌트에 variant prop 추가

```javascript
function Logomong({ size, animate, glow, circleBg, variant = 'default' }) {
  const imageUrl = LOGOMONG_VARIANTS[variant] || LOGOMONG_VARIANTS.default;
  // ... (이미지 렌더링)
}
```

### 7.1 문제 #1: 한글 경로 인식 실패

#### 발생 시점
Phase 1 - 폴더 진입 시도

#### 에러 메시지
```bash
$ ls -la "/Users/bluediamond/Desktop/Junho 의 MacBook Pro 14/말씀의지혜/로고몽"
ls: /Users/bluediamond/Desktop/Junho 의 MacBook Pro 14/말 씀 의 지 혜 /로고몽: No such file or directory
```

#### 원인
"말씀의지혜"가 "말 씀 의 지 혜"로 인식됨 (한글 사이 공백 인식 문제)

#### 해결
Finder에서 폴더를 직접 터미널로 드래그 → 정확한 경로 자동 입력

---

### 7.2 문제 #2: 명령어 중복 실행 (cmdand 에러)

#### 발생 시점
Phase 1 - 11개 일괄 변경 명령어 실행 시도

#### 에러 메시지
```bash
% mv "mv "보너스1) 기도하는 로고몽.png" ...
cmdand cmdand cmdand cmdand cmdand cmdand cmdand
```

#### 원인
복사한 명령어 앞에 이전 입력의 잔재(`mv`)가 남아 있어서 명령어가 중복됨

#### 해결
1. `Control + C` 로 강제 종료
2. 한 줄씩 따로 실행하는 방식으로 전환

---

### 7.3 문제 #3: 포즈 1~6번 변환 실패

#### 발생 시점
Phase 1 - 포즈 파일 변환 단계

#### 에러 메시지
```bash
mv: rename 포즈1) 로고몽 데뷔의 첫 순간 - 시청자가 평생 기억할 표정.png to pose1_debut.png:
No such file or directory
```

#### 원인
파일명에 "엠대시(—)" 문자가 들어있는데, 명령어에는 "하이픈(-)"으로 입력됨.
- "—" (긴 줄, U+2014)
- "-" (짧은 줄, U+002D)
- 컴퓨터에게는 완전히 다른 문자

#### 해결
와일드카드(`*`) 사용으로 전환:
```bash
mv 포즈1*.png pose1_debut.png
```

→ 복잡한 특수문자 입력 불필요, "포즈1로 시작하는 모든 파일" 매칭

---

### 7.4 교훈

> **한글 파일명·특수문자가 들어간 파일은 와일드카드(`*`)로 처리하는 것이 가장 안전하다.**

**일반 원칙**:
- 자동화 가능한 작업은 **터미널 일괄 처리**가 빠르지만
- 한글·특수문자 포함 시에는 **와일드카드** 또는 **Finder 직접 변경**이 안전
- **한 줄씩 따로 실행**이 디버깅에 유리

## 9. 배운 것들

### 9.1 기술적 배움

#### 1. 파일명 표준화의 중요성
- 한글·특수문자는 다양한 시스템에서 인코딩 문제 발생
- **영어 + 언더스코어 + 소문자**가 가장 안전
- 이 원칙은 폴더명에도 동일 적용

#### 2. 와일드카드의 위력
```bash
# 까다로운 입력
mv "포즈1) 로고몽 데뷔의 첫 순간 — 시청자가 평생 기억할 표정.png" "pose1_debut.png"

# 단순하고 안전
mv 포즈1*.png pose1_debut.png
```

#### 3. jsDelivr CDN의 가치
- GitHub만으로는 미디어 스트리밍에 부적합
- jsDelivr이 자동으로 CDN 역할 수행
- 무료 + 무제한 + 글로벌 노드

#### 4. Git의 일관성
```
git add . → git commit → git push
```
이 단순한 흐름이 매번 정확히 작동.
**자동화의 힘**.

### 9.2 작업 흐름 배움

#### 1. 단계별 분할의 효과
```
한 번에 → 11개 명령어 일괄 실행 시도 → 실패
나누어 → 한 줄씩 차례 실행 → 성공
```

복잡한 작업일수록 **작은 단계로 분할**하는 것이 안전.

#### 2. 안전 장치의 중요성
- 코드: variant 누락 시 default 폴백
- 이미지: 로드 실패 시 🐑 이모지 폴백
- 명령어: `&&` 로 연쇄 실행 시 하나만 실패해도 멈춤

→ **방어적 설계**가 사용자 경험을 보호

#### 3. 검증의 가치
각 Phase마다 검증:
- Phase 1: `ls *.png` 로 파일명 확인
- Phase 3: GitHub에 폴더 구조 보이는지 확인
- Phase 4: jsDelivr URL로 이미지 직접 확인
- Phase 5: 코드 구문 검증 + 푸시 결과 확인

→ **각 단계 완료 확인 후 다음으로** 진행하는 습관
