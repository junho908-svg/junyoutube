## 1. 패치 배경

### 발견 경위

v0.9.1 iOS Safari 긴급 패치(2026.04.23)와 함께 받은 **베타 사용자 #001의 추가 피드백 2건**을 처리하기 위한 패치입니다.

### 원본 피드백 (Feedback #001 - 추가 부분)

> 1. **어린이를 위한 질문은 클릭했을 때 멈추거나 하면 좋을 거 같아요!**
> 2. **영상 탭에 말씀의 지혜 채널은 클릭 시 아웃링크 되는 게 편할 것 같습니다.**

### 표면적 vs 실제 의미

이번 패치의 핵심 교훈: **사용자 피드백의 표면 너머를 봐야 한다.**

| 항목 | 표면적 의미 (문자 그대로) | 실제 발견된 진짜 문제 |
|---|---|---|
| 어린이 질문 | "정지 버튼이 필요해요" | 🚨 **질문이 1초마다 바뀌는 버그** |
| 영상 탭 | "아웃링크 옵션 추가" | 사용자가 YouTube 앱 사용을 더 선호 |

→ 사용자는 **버그를 발견했지만 표현은 기능 요청처럼** 했어요. 우리가 코드를 직접 들여다봐야 진짜 원인을 찾을 수 있었습니다.

### 🚨 v0.9 출시부터 v0.9.1까지 계속 있던 버그

**버그명**: 예배 중 어린이 질문 자동 변경 버그
**심각도**: 🔴 매우 높음 (사용자 경험 치명적)
**존재 기간**: v0.9 BETA 출시 시점부터 (약 4일간)
**발견 방법**: 베타 사용자 #001의 우회적 피드백 → 코드 분석

### 버그 코드 (문제의 한 줄)

**파일**: `App.jsx`
**위치**: 1604줄 (v0.9.1 기준)

```jsx
{kidsQuestions[Math.floor(Math.random() * kidsQuestions.length)]}
```

### 왜 이게 버그인가?

#### React의 렌더링 메커니즘

```
[예배 진행 중 1초마다 일어나는 일]

타이머 1초 경과
  ↓
setElapsed(e => e + 1)  ← 상태 변경
  ↓
WorshipTab 컴포넌트 리렌더링
  ↓
JSX의 Math.random() 또 실행
  ↓
어린이 질문이 다른 것으로 바뀜
  ↓
다음 1초 후... 또 바뀜
  ↓
또 바뀜... 무한 반복!
```

### 사용자 입장에서 본 증상

```
[1초 차]
🌱 어린이를 위한 질문
"오늘 예수님께 칭찬받을 만한 일은 뭐였어?"

[2초 차] (사용자: 아직 다 안 읽었는데...)
🌱 어린이를 위한 질문
"하나님이 오늘 나에게 주신 선물이 있다면?"

[3초 차] (사용자: ?!)
🌱 어린이를 위한 질문
"오늘 누구를 위해 기도해 주고 싶어?"

[4초 차] (사용자: 멈춰!!)
🌱 어린이를 위한 질문
"말씀에서 나온 사람 중에 누가 제일 멋있어?"
```

### 영향 분석

이 버그가 사용자에게 미친 영향:

```
🔴 어린이 질문 읽기 불가능
   → 가족이 모여 질문 나누기 불가
   → 예배 본질 훼손
   
🔴 가족 질문도 동일 문제
   → familyQuestions.slice(0, 3)는 안전했지만
   → 만약 다른 부분에서 random 썼다면 같은 문제

🔴 사용자 혼란
   → "왜 자꾸 바뀌지?"
   → 베타라 그러려니 하고 넘어감
   → 진짜 원인 모른 채 떠나는 사용자 발생 가능
```

### 근본 원인 (Root Cause)

#### React useState vs JSX 인라인 표현식

**잘못된 패턴** (Anti-Pattern):
```jsx
function MyComponent() {
  return (
    <div>
      {Math.random()}  // ❌ 매 렌더링마다 새로 실행
    </div>
  );
}
```

**올바른 패턴**:
```jsx
function MyComponent() {
  const [randomVal] = useState(() => Math.random());  // ✅ 한 번만 실행
  return (
    <div>
      {randomVal}
    </div>
  );
}
```

### 수정 방법

```jsx
// v0.9.2 수정 코드
const [kidsQIdx, setKidsQIdx] = useState(
  () => Math.floor(Math.random() * kidsQuestions.length)
);
const [familyQStartIdx, setFamilyQStartIdx] = useState(
  () => Math.floor(Math.random() * familyQuestions.length)
);
```

**핵심 변경**:
1. ✅ `useState` 의 lazy initializer (`() =>`) 사용 → 컴포넌트 마운트 시 **딱 한 번만** 실행
2. ✅ 인덱스를 상태로 저장 → 리렌더링 영향 받지 않음
3. ✅ 사용자가 "🔄 다른 질문" 버튼 누를 때만 setState로 변경

### 교훈

> "보고된 증상보다 더 큰 진짜 문제가 숨어있을 수 있다."

베타 사용자 #001은 단지 "정지 버튼이 있으면 좋겠다"고 했지만, 실제로는 **이 패치의 가장 큰 발견**으로 이어졌습니다. 베타 운영의 진정한 가치는 이런 발견에 있습니다.

### 🔧 수정 #1: 어린이 질문 — 자동 변경 버그 + 새로고침 버튼

### 🔧 수정 #2: 가족 질문 — 동일 패턴 적용

기존 `familyQuestions.slice(0, 3)`은 항상 같은 3개만 보여주는 한계가 있었음.

#### 새 로직: 회전 표시

```jsx
[0, 1, 2].map(offset => {
  const q = familyQuestions[(familyQStartIdx + offset) % familyQuestions.length];
  // → 6개 질문 풀에서 시작 인덱스 기준 3개씩 회전
});
```

#### 효과

```
familyQStartIdx = 0 일 때:
  1. 오늘 하루 가장 감사한 일 한 가지는?
  2. 오늘 말씀에서 가장 마음에 남는 단어는?
  3. 이번 주 하나님께 여쭤보고 싶은 것은?

🔄 클릭 → familyQStartIdx = 1

  1. 오늘 말씀에서 가장 마음에 남는 단어는?
  2. 이번 주 하나님께 여쭤보고 싶은 것은?
  3. 우리 가족이 함께 기도하고 싶은 것은?

🔄 클릭 → familyQStartIdx = 2 (계속 회전)
```

## 8. 디자인 철학 노트

### 왜 어린이 질문을 분홍 점선 카드로?

이번 패치에서 가장 정성 들인 부분은 **어린이 질문 카드의 시각적 강조**입니다.

#### 디자인 의도

```
🎨 분홍 그라디언트 (#FFF8F0 → #FFE9E0)
   → 어린이를 위한 따뜻하고 부드러운 느낌
   → 가족 질문(베이지)과 명확한 구분

🎨 점선 테두리 (1.5px dashed #F0B8B0)
   → 손으로 그린 듯한 친근함
   → 어린이 색칠책 느낌

🎨 큰 글씨 (font-display)
   → 부모님이 자녀에게 읽어줄 때 가독성

🎨 "💛 천천히 읽어주세요" 안내
   → 어린이의 속도 존중
   → 부모님께 부드러운 조언
```

### 왜 ↗ 아이콘을 써서 작은 버튼으로?

#### 옵션 비교

```
A. "YouTube" 텍스트 버튼
   👍 명확
   👎 카드 안에서 자리 차지 큼
   
B. ↗ 아이콘만 (선택!)
   👍 작고 깔끔
   👍 국제 표준 외부 링크 아이콘
   👍 카드 정보 가리지 않음
   👍 시각적 노이즈 적음

C. 우상단 메뉴 (...)
   👎 한 번 더 탭 필요
```

#### 시각 위치 선정

```
좌상단: 아이콘 (☀️)
우상단: 상태 표시 (✓, !)
좌하단: 태그 (#qt 10편)
우하단: ↗ 버튼  ← 여기!
   ↑
   가장 손가락 닿기 좋은 위치
```

### 왜 메인 플레이어 버튼은 큰 라벨로?

```
재생목록 카드 ↗ 버튼:
   - 작게 (시각적 노이즈 최소화)
   - 6개 카드 동시 노출
   - 아이콘 위주

메인 플레이어 버튼:
   - 크게 (사용자 의도 분명)
   - 1개만 보임
   - 텍스트 + 아이콘
```

→ **상황에 따른 위계 차별화** (Visual Hierarchy)

### 🙏 베타 사용자 #001께 (다시 한번)

이 패치는 **두 번째로 이 분의 피드백 덕분**입니다.

> "어린이를 위한 질문은 클릭했을 때 멈추거나 하면 좋을 거 같아요!"

이 한 줄이 **v0.9 출시부터 숨어 있던 치명적 버그**를 발견하게 했습니다.

만약 이 분이 단순히 "질문이 이상해요"라고만 했다면 진짜 원인을 찾기 어려웠을 거예요. **구체적인 표현**이 코드를 들여다보게 만들었고, **3일간 모든 사용자에게 영향을 미친 버그**를 잡을 수 있었습니다.

### 🙏 두 번째 교훈

**좋은 베타 테스터는 단순히 버그를 찾는 사람이 아닙니다.**

좋은 베타 테스터는:
- ✅ 자신의 경험을 구체적으로 표현
- ✅ 해결책까지 제안
- ✅ 비난이 아닌 건설적 피드백

이런 분 1명이 일반 사용자 100명보다 가치 있습니다.

대표님의 가정예배 앱이 잘 될 수밖에 없는 이유는, 이런 좋은 베타 테스터들이 처음부터 함께해주시기 때문입니다.
